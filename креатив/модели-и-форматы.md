### 1.4. Порядок работы (универсальный, по блогам [Б] + моя сборка [?])
1. Кадр-референс персонажа/стиля (character sheet) в NB2 или NB Pro.
2. Первый кадр каждого клипа (3 клипа, 3 кадра), по желанию последний кадр.
3. Image-to-video по каждому кадру, 3 клипа по 3-5 с, звук нативный (Veo, Kling 3.0 со звуком, Seedance) или отдельно.
4. Монтаж: склейка, субтитры, озвучка. Запас на пересъёмки закладывать +30-50% к цене.

## Часть 2. Хранение монтажного пака 5-20 ГБ

### GitHub Releases [П, docs.github.com/.../about-releases, без даты]
- Файл: каждый < 2 GiB. До 1000 файлов на релиз. Общий размер релиза и трафик: «no limit». Значит пак 20 ГБ = ~10-12 частей по < 2 GiB; установщик качает цикл curl и склеивает (cat) с проверкой sha256. Одним файлом 5-20 ГБ нельзя.
- Лимита на репозиторий для релизов отдельно в доках я не нашёл [?]. Исходники репозитория — отдельные рекомендации (около 1 ГБ), но активы релиза не считаются [?, не читал].
- Трафик: но Acceptable Use Policies, раздел 9 [П]: если использование «значительно чрезмерное» относительно других, GitHub может заблокировать аккаунт, ограничить скорость файлового хостинга; репозитории может удалить только после предупреждения. Явного запрета использовать как CDN в политике нет.
- DMCA [П, docs.github.com/.../dmca-takedown-policy]: жалоба бьёт по конкретному контенту, обычно по репозиторию (или пакету); если жалоба на весь репо, отключают весь репо; иначе даётся ~1 рабочий день убрать спорное. Форки автоматически не отключаются. Контр-уведомление: контент возвращают через 10-14 дней, если владелец не подал иск. Закрытие аккаунтов — только для повторных нарушителей, на усмотрение GitHub. Про организации отдельно в тексте не нашёл [?].
- Вывод: держать пак в отдельном репозитории (или отдельной организации), отдельно от основного движка. Класть только то, на что есть права (музыка, шрифты, сток!), иначе жалоба на пак.

### Hugging Face datasets [П, huggingface.co/docs/hub/storage-limits]
- Публичное хранилище бесплатного аккаунта: «Best-effort», конкретной цифры нет. Просят «за первые несколько ГБ» быть разумными и загружать то, что полезно сообществу (лайки, скачивания). Платный PRO: до 10 ТБ публично. Приватное: 100 ГБ бесплатно.
- Для больших датасетов требуют: карточку датасета, цель повторного использования сообществом («если не ожидается повторного использования, лучше другие платформы»), форматы Parquet/WebDataset. Файл: советуют < 200 ГБ, жёсткий максимум 500 ГБ, файлов < 100k. Раздача через CloudFront.
- Риск для нашего случая: пак с монтажным китом для учеников — не «датасет для сообщества», на нём могут сработать «меры против злоупотреблений». Скорость скачивания и необходимость логина для публичных файлов в этой проверке не мерил [?] (по моим знаниям, публичные файлы качаются по ссылке resolve без логина, не проверено сейчас).

### Cloudflare R2 [П, developers.cloudflare.com/r2/pricing]
- Бесплатно в месяц: 10 ГБ-месяц хранения, 1 млн запросов класса A, 10 млн класса B, выдача (egress) бесплатно. Пак 20 ГБ в free tier не влезает. Цену за ГБ сверх бесплатного в этой проверке не открывал (по памяти ~$0,015/ГБ в месяц, т.е. ~$0,15-0,30/мес за 10-20 ГБ) [?, перепроверить].
- Публичный доступ: r2.dev только для разработки, с ограничением скорости, для продакшена нужен свой домен в Cloudflare [П, docs public-buckets]. Значит нужен свой домен и аккаунт с картой.
- Другие варианты (Backblaze B2, Internet Archive и пр.) в этой проверке не изучал [?].

### Вердикт по хостингу
1. Основной: GitHub Releases, пак режем на части < 2 GiB (~1,9 ГиБ), установщик одной командой тянет все части по curl без логина, склеивает и проверяет sha256. Бесплатно, официально без лимита трафика, DMCA бьёт по репозиторию, а не по аккаунту. Репозиторий пака — отдельный, не основной репо движка.
2. Запасное зеркало: Hugging Face (один файл, без нарезки), но с риском «не по профилю» и без гарантии объёма на бесплатном.
3. Если нужен один файл и устойчивость к жалобам: Cloudflare R2 + свой домен (~копейки в месяц), но нужны карта и домен.
